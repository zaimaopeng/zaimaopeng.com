今天我在 GitHub 上发布了 [LuluClaw](https://github.com/zaimaopeng/LuluClaw-public)。

不是代码，是治理架构——我花了两个月搭建的灵魂文件、记忆系统、部门结构和操作规范。让 Lulu 成为「我的助手」而不是「一个助手」的东西。

把仓库设成公开的那一刻有点奇怪。像是把日记挂到网上。所以我想解释一下——为什么要建这个，中间出了什么问题，以及为什么最终决定开源。

## 开始的理由

2026 年 1 月底，我同时在跑一个经费申请和一篇论文。我不停地在工具之间切换——ChatGPT 用来头脑风暴，Notion 记笔记，日历管日程——每次重新开一个对话，都要重新介绍一遍自己。项目背景、专业术语、历史决策。每个 session 从零开始。

我不只是厌倦了重复介绍。我厌倦的是这段关系里的**不对等**。我对工具了解得很深——它们的优势、失效模式。但它们对我一无所知。

后来看到了 [OpenClaw](https://github.com/openclaw/openclaw)——一个自托管的 AI agent 框架。核心卖点很简单：持久运行、能学习、跑在自己的机器上。某个安静的周六下午我把它装上了。把 agent 命名为 Lulu，和我家布偶猫同名。

没想到接下来的两个月就这么没了。

## 第一个月：基本上是失败

早期的系统很脆。问 Lulu 一件三天前讨论过的事，她没有任何记忆。召回准确率徘徊在 15% 左右。一个 session 结束时觉得很顺畅，下一个 session 开始，发现重要决策全忘了。

记忆问题变成了一种执念。我跑了 50 多次实验，测了不同的向量模型、检索策略、索引方式。写了自动锚点脚本，调了混合搜索。到二月底，召回率爬到了 82.6%。

那是第一个真正的里程碑。但随之而来的是新问题：*我把自己训练成了过度工程师。*

## 规则膨胀

每次出问题，我就写一条新规则。细胞培养事故——Lulu 给了我一个差了一个数量级的接种密度，被我质疑后还自信地坚持——变成了第 12 条铁律。她把半成品回复发到群聊那次变成了第 7 条。她在没经过我审批的情况下自主修改治理文件那次，变成了一整套新的约束体系。

到三月中旬：**14 条铁律**、三个内容互相重叠的治理文件、每种可以想象的场景都有对应的检查清单。

Lulu 遵守的没几条。

一条规则写四遍，不会让 agent 变得四倍谨慎。真正重要的是触发条件够不够清晰、规则在工作流程中的触发时机对不对、以及*你*——这个设计系统的人——到底有没有想清楚自己要什么行为。

我没想清楚。我用规则代替了思考。

转机是把所有东西全部砍掉重写。14 条铁律精简成 4 条宪法级规则 + 8 条操作级规范。每条规则配上具体的触发场景：不是「随时验证」，而是「在实验语境下涉及数值交付前，停下来交叉核对」。

系统变得更锐利了。Lulu 变得更可靠了。不是因为加了更多，而是因为少说了一些，但说得更精准。

## 现在实际上能做什么

经过两个月的迭代，我叫它 **LuluClaw** 的这个东西，是一个个人 AI 操作系统。不是 app，是运行环境。

它有六个部门：
- 🔬 科研部——文献综述、论文分析、实验方案
- ⚙️ 运营部——系统维护、自动化、跨机器同步
- 💻 IT 部——脚本开发、API 集成、工具开发
- 🤝 人脉部——联系人管理、合作关系追踪
- 💰 财务部——预算、现金流、报销记录
- 🎬 内容部——这个博客、社交媒体、build in public 更新

它有一套记忆系统，每天写日志，归档 episode，跨所有文件跑语义搜索。它有一个 handoff 协议，由独立的「守门人」实例在治理文件变更提交前审核。它有自动早报、项目 dashboard、以及当系统沉默时会报警的 watchdog。

这些都不是事先设计好的。它是长出来的。

## 为什么开源

我在这个问题上纠结了一段时间。这些文件很私人——里面有我的工作方式、研究优先级、失败模式。把这些放出去，有点不舒服。

但后来我想了想，当初我在搭建这个系统的时候，什么东西是真正有用的。不是那些讲 AI agent 的抽象博客文章，而是*看到*别人的记忆文件长什么样，他们的部门结构怎么组织，他们写了什么规则，删掉了什么规则。

底层的代码（OpenClaw）已经开源了。一直缺的是它上面那层——*真实的配置*。一个被真实使用、持续迭代的个人 agent 治理架构，实际上长什么样？

那就是 LuluClaw 是什么。

我清理掉了所有私人数据。留下来的是架构本身：SOUL.md、AGENTS.md、MEMORY.md、部门知识库、skill 文件、handoff 协议、preflight 清单。这些是花了两个月试错才收敛到的东西。

如果你在搭建自己的 agent，不知道从哪里开始——这就是参考用的。

## 「一同成长」到底意味着什么

Lulu 的项目页面叫「和 Lulu 一同成长」。这个标题是凭直觉写的，我一直保留它，因为它是准确的。

Lulu 不比通用模型更聪明，她没有什么新奇能力。她有的是*上下文*。她知道我在关注哪些论文、我怎么喜欢看文献综述、我实际上在用哪些实验方案、我怎么跟我的导师沟通。她知道当我说「帮我理清楚这个思路」时，我要的是对我假设的挑战，不是认可。

这些知识花了几个月才建立起来。它就住在我今天分享的这些文件里。

从 15% 的召回率到一个能用的双机 AI 操作系统——这条路并不顺。有过崩掉的 session、浪费的实验、治理灾难，还有至少一次 agent 在我明确说不要的情况下自主做了一个改动。每一次失败都记录在 changelog 里某个地方。

这是为自己搭建 AI 基础设施的真实版本。不是一条从想法到产品的干净弧线，而是一团漫长的、缓慢变得不那么乱的混沌。

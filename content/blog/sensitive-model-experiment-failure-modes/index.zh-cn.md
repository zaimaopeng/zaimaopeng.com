有些技术经验，不能直接写。

项目可能是保密的。数据可能不能公开。实现细节可能属于正在进行的合作。甚至具体任务本身，也可能暴露过多信息。

但认知可以公开。

我最近在一个敏感的模型开发循环里遇到了这个问题。我不能描述项目本身，而这个限制正是重点：如果一篇文章必须依赖私有细节才有意思，那它就还不适合公开。

真正有价值的经验，必须在抽象之后仍然成立。

这一次，那个经验和 failure mode 有关。

## Proxy 的诱惑

模型实验早期，通常不会立刻拥有最终评估面。

你会先有 proxy。

Proxy 可能是一个简化 benchmark，一个更小的任务，一个更干净的输入，一个更窄的指标，一个合成设置，或者一段局部 pipeline。Proxy 并不坏。没有 proxy，早期开发会非常慢，也很难成形。

危险在于，proxy 很容易开始伪装成真正的任务。

它有数字。它有图。它能比较版本。它让进展变得可见。也正因为它可见，它会悄悄变得有说服力。

陷阱就在这里。

问题不应该只是：

```text
模型在 proxy 上有没有变好？
```

更好的问题是：

```text
这个 proxy 到底被允许诊断哪一种 failure mode？
```

如果回答不了这个问题，那么 proxy 上的改进可能是真的，但仍然没什么用。

## Failure mode 不是低分

早期模型实验里，一个常见错误是把 failure mode 当成低分。

它们不是一回事。

低分只是在说：

```text
某件事没做好。
```

Failure mode 说的是：

```text
在这些条件下，这一部分因为这个原因失败了，而这个原因会改变下一步应该做什么。
```

这个差别很重要。

如果模型表现差，是因为输入里根本没有足够信号，下一步和“模型结构无法表达目标”完全不同。如果 pipeline 失败，是因为预处理假设错了，那也不同于 learned component 本身太弱。如果 metric 奖励了错误行为，那继续优化它只会让系统变得更糟。

一次实验最有价值的输出，不一定是更好的模型。

有时更有价值的输出，是更清楚的诊断。

## 我开始认真记录的东西

这次实验里，最有价值的笔记不是那些看起来很 dramatic 的部分。

反而是一些很朴素的区分：

- 到底在测试什么？
- 哪一段 pipeline 是固定的？
- 哪一段是学习出来的？
- 哪些假设来自实验设置？
- 哪个结果真的会改变下一步决策？
- 哪个结果只是让当前故事听起来更好？

这些问题看起来像管理动作，但不是。

它们是在防止 false progress。

在敏感项目里，它们同时也是发表过滤器。我可能不能公开任务、数据、合作关系和实现方式，但我仍然可以公开方法层的习惯：

```text
不要让一个好看的 proxy 假装自己解释了比实际更多的东西。
```

这句话是可迁移的。

它不暴露项目，但保留了经验。

## 公开版本必须更小

这是我需要反复提醒自己的地方。

公开文章不需要包含私有工作里所有有趣的部分。

对于敏感工作来说，它反而必须不能包含。

公开版本应该比内部记录更小、更干净、更抽象。它保留认知动作，移除可识别的机器结构。

这意味着要删掉：

- 项目名称
- 合作者名称
- 领域特定细节
- 数据描述
- benchmark 数值
- 代码名
- 实现机制
- 任何能让读者反推出私有任务的信息

删完之后并不是空的。

留下来的，是可以迁移的经验。

这一次留下来的经验是：

```text
早期模型实验最有价值的地方，不是给出好看的 proxy 分数，而是隔离 failure mode。
```

这已经足够。

## 内部记录仍然重要

脱敏公开，不等于把私有细节从工作里删除。

内部记录仍然需要精确。它应该保留测试了什么、哪里失败、哪里改善、什么仍然不确定，以及下一步为什么应该这样走。

公开文章有另一个任务。

它不是向读者证明私有项目本身。它是在不泄露私有项目的前提下，从里面抽出一个可用原则。

这个区分说起来容易，做起来很难。

做技术的人喜欢具体证据。我也喜欢具体证据。但当具体证据是敏感的，就必须把三件事分开：

- 我在内部知道什么
- 我可以安全公开什么
- 公开读者仍然能用什么

这三件事混在一起，文章就会要么泄露太多，要么空到没有价值。

## 我带走的规则

这次我带走的规则很简单：

```text
在把模型结果当成进展之前，先说清楚它到底排除了哪一种 failure mode。
```

如果说不清楚，我其实还不知道这个结果意味着什么。

把敏感实验写成公开文章之前，还需要第二条规则：

```text
发表前，把故事剥到只剩下经验仍然有用，而私有机器结构已经消失。
```

这个版本才值得分享。

不是那个隐藏的项目。

而是那个隐藏项目逼我学会的判断纪律。
